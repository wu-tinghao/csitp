# 要求回顾与路线选择

[返回首页](../README.md)

## 1. 按用户原意筛选

最初的四条要求是：核心为产线表面缺陷检测；有 YOLOv8 一类轻量边缘模型；边缘算力受限、云端算力充足且参与协同；提供对应 GitHub 代码。近三年按 2023-11-09 至 2026-11-09 处理。

后续明确：**不强制云端真实复检，有云边协调即可，重点探索多种可行技术路线。** 因此云端训练、模型下发、迁移适配、聚合、卸载都可研究。云端可以是实验室 GPU 服务器或厂内私有服务器，不必购买公有云。实际实验仍应给出云、边两端资源配置。

论文与工程分开判定：

- 论文：核实题名、日期、具体任务、云边职责和作者代码对应关系。
- 工程：核实源文件、部署脚本和许可证；不借用别的论文指标。
- 组件：可拼成我们自己的系统，但不意味着原组件已完成整套产线质检。
- 只有看板/消息通知的工程：作为通信或运维参考，不能证明云端提高检测精度。

板卡实测是证据质量分级，**不是额外规定没有板卡实测就完全排除**。对尚未实测的轻量化方案明确标注，不宣称性能。

## 2. 推荐路线

### R1：边缘实时检测，云端训练与版本发布——最适合作为基础

**流程：** 图像在边缘推理 → 抽样/疑难图像与人工标签回流 → 云端训练和验证 → 压缩/导出 → 定向下发 → 边缘校验、切换、失败回滚。

**解决什么：** 新产品、光照变化、缺陷分布变化导致旧模型逐渐失效；同时避免小设备承担重训练和每张图联网的成本。

**例子：** [软包装论文](https://doi.org/10.3390/app16083786)提供持续更新设计；[AWS 样例](https://github.com/aws-samples/sm-qai-hub-examples)提供云训练与编译代码；[DDA](https://github.com/awslabs/DefectDetectionApplication)提供设备与模型发布管理。三者互为参考，**不是彼此配套仓库**。

**优点：** 边缘推理延迟不依赖逐帧网络往返；模型训练可使用云 GPU；版本管理容易演示。
**缺点：** 无法实时挽救所有当前帧漏检；高质量标签回流和发布门控需要实现；更新不一定提高精度。
**边缘适配：** 好。优先先测 YOLOv8n，再评估分辨率、FP16/INT8 对细小缺陷召回的影响。
**编排研究点：** 训练触发条件、验证门控、定向/灰度发布、原子切换和回滚。具体实现是本项目建议，不宣称所有参考已具备。

### R2：边缘初检，疑难样本按需上云——最贴合你的“不确定再上报”

**流程：** 小模型推理 → 评估疑难程度及剩余时限 → 本地判定/上传云模型 → 回传或超时进入待复核 → 记录最终结果和模型版本。

**例子：** [Sensors PCB 论文](https://doi.org/10.3390/s24185921)提供缺陷任务依据；[Sedna JointInference](https://github.com/kubeedge/sedna/tree/main/examples/joint_inference/helmet_detection_inference)提供通用协同代码。原示例是安全帽和 YOLOv3 系列，需要改造模型、输入输出、类别和评估数据。

**优点：** 能把算力集中到困难图像；上传比例、召回率和时延构成可量化的研究问题。
**缺点：** 网络、排队和上传会增加长尾时延；云模型也可能错；阈值过低上传太多，过高漏掉困难样本。
**边缘适配：** 好，但路由特征本身也消耗计算。
**编排研究点：** 固定阈值 vs 置信度/质量/带宽/队列/截止时间联合路由。

注意：没有检出框并不等于“确信合格”。对无框图像加入抽检，考虑模糊、遮挡、异常分布和多帧不一致；小框的分数不是整件产品合格概率。云边判定冲突不直接采用云端结论，应预设人工复核或隔离策略，并统计冲突率。

### R3：云端预训练模型库，边缘少样本迁移适配——适合频繁换型

**例子：** [Tang 等，2026](https://doi.org/10.1007/s11227-025-07993-2)，题名为 An improved transfer learning for surface defect detection in edge-cloud continuum environments。出版社摘要明确“云端提供预训练权重，边缘小数据微调”，不能改写成“全部云端微调”。

**解决什么：** 新钢材/新工件样本少、从头训练成本高。
**优点：** 利用已有知识，适配产品变化；可比较同等标注量下的效果和训练耗时。
**缺点：** 作者源码未核实；边缘训练需要显存、内存和时间，与“极弱边缘端”有冲突；摘要精度改善不证明微型设备可训练。
**采用条件：** 边缘是有 GPU 的工控机/网关、可在停线时微调。若只有低功耗推理板，将适配训练迁到云端，归入 R1 的自拟改造方案。
**代码落点：** 可借用 [PCB YOLOv8](https://github.com/Dingshichun/PCB-Defect-Detection-System-Based-on-YOLOv8) 或 [钢材 YOLOv8](https://github.com/YfengJ/steel-defect-detection)训练组件；二者不是 Tang 论文官方实现。

### R4：多产线联邦学习——确有表面缺陷示例，但不宜首发

**例子：** [Sedna 磁瓦缺陷联邦学习](https://github.com/kubeedge/sedna/tree/main/examples/federated_learning/surface_defect_detection)，属于较早的框架示例，不算近三年论文。

**流程：** 多边缘本地训练 → 云端聚合参数 → 各节点获得更新模型。
**优点：** 跨产线共享模型能力，减少集中原始图像的需求。
**缺点：** 边缘必须能训练；多节点部署、数据非独立同分布和通信轮次使实验复杂；参数交换不自动等于隐私保证。
**边缘适配：** 普通小板不理想；有 GPU 的边缘网关更合理。
**采用条件：** 有至少两组产线数据、训练资源和明确的数据不出厂诉求。示例是否能直接替换 YOLO 必须另验，不能只换模型文件。

### R5：早退分支/网络切分——算法研究备选

**例子：** [Reliability analysis and Terahertz characterization of circuit board defect employing branchy neural network in edge-cloud fusion architecture](https://doi.org/10.1016/j.engappai.2024.109468)，EAAI 2024，提出 YOLOX BranchyNet；未核实到作者公开 GitHub。

**流程设想：** 边缘浅层/早退分支处理容易样本，难样本继续深层或发送中间特征；具体切分策略需全文和实现确认。
**优点：** 可研究不同计算深度与传输成本的折中。
**缺点：** 分支训练、算子兼容和中间特征传输较复杂，特征可能比原图还大；论文涉及太赫兹成像，不能直接等同普通工业相机表面检测。
**代码参考：** [Neurosurgeon 第三方复现](https://github.com/Tjyy-1223/Neurosurgeon)，对应经典 2017 方法，非本篇代码，非近三年工作；许可证和复现仍待查。
**建议：** 文献综述中保留，不作为第一阶段交付承诺。

## 3. 独立通信能力：离线自治和重连补传

[lucamaf/edge-defect-detector](https://github.com/lucamaf/edge-defect-detector) 的 Jetson 检测与 Artemis 持久队列说明，可供 R1/R2 参考。它把结果同步到 OpenShift，未核实到云端复检或自动重训练。因此应写成“云边数据同步与故障恢复组件”，不升级为云端 AI 计算案例。

## 4. 最终取舍

优先顺序：**R1 基础 → R2 可插拔策略 → R3 换型实验；R4/R5 仅在资源和时间允许时深入。**

首个演示对象建议 PCB 六类表面缺陷；若已有钢材样本或真实产线资源，优先现有数据。软包装参考包含空袋、连袋等过程缺陷，最终任务需限定到你实际研究的表面损伤、印刷/颜色缺陷，不能把全部包装异常都写成表面缺陷。
